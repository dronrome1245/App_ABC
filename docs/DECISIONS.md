# Decision log

## 2026-08-19 — D001: Android-only MVP

Первая версия — нативное Android-приложение на Kotlin/Jetpack Compose.

## 2026-08-19 — D002: Названия букв, без звуков

MVP тренирует визуальную букву и её название. Фонетика/звуки букв пока не внедряются.

## 2026-08-19 — D003: Уровни + адаптивное повторение

Прогресс оформляется уровнями и наградами, но учебный движок продолжает повторять старые буквы и чаще возвращает слабые.

## 2026-08-19 — D004: Статистика и слабые буквы

Обязательны статистика по каждой букве, список проблемных букв и confusion matrix. Слабые буквы можно тренировать отдельно.

## 2026-08-19 — D005: Никакой суточной блокировки

3–7 минут — рекомендуемая сессия, а не лимит. После неё и после повторного входа занятия доступны.

## 2026-08-19 — D006: Рисование исключено

Рисование/проверка написания буквы не входят в MVP, чтобы ускорить разработку и тестирование.

## 2026-08-19 — D007: Слоги/слова позже

`МА → МО → МУ`, слова и чтение — отдельное развитие после базового тренажёра букв.

## 2026-08-19 — D008: Speech recognition отдельным экспериментом

Автоматическое распознавание произнесённого названия буквы планируется, но не блокирует MVP. Неуверенное распознавание не считается ошибкой ребёнка.

## 2026-08-19 — D009: Сначала семейный пилот, затем решение о публичном продукте

Первая цель — работающий локальный инструмент для реального домашнего использования. Backend, аккаунты, массовая продуктовая инфраструктура и требования публичного продукта не должны усложнять ранний пилот.

Решение о публикации принимается после накопления реальной статистики и проверки UX/полезности.

## 2026-08-19 — D010: Успех измеряется метриками знания, а не активностью

Основные метрики: accuracy по букве, response time, delayed success/retention, confusion rate и количество устойчиво освоенных букв.

Звёзды, минуты, открытые уровни и серия занятий — только мотивационные/активностные показатели.

## 2026-08-19 — D011: LearningPolicy и Curriculum версионируются

Изменения порогов mastery, весов, retry, level unlock и curriculum не должны происходить неявно.

После M1 должны использоваться отдельные версии:

- `learningPolicyVersion`;
- `curriculumVersion`;
- `databaseSchemaVersion`.

Изменение поведения требует обновления документации и тестов.

## 2026-08-19 — D012: Parent mode нужен в MVP

Детский основной поток остаётся простым. Статистика, ручной выбор букв, настройки и сброс прогресса относятся к родительскому режиму/настройкам и не должны загромождать детский экран.

Сложная авторизация родителя для семейного MVP не требуется.

## 2026-08-19 — D013: Локальные данные и privacy by default

До отдельного решения:

- нет backend;
- нет аккаунтов;
- нет analytics SDK;
- нет рекламных SDK;
- нет передачи учебной статистики разработчику;
- аудио ребёнка не сохраняется.

Микрофон запрашивается только при явном использовании экспериментального ASR-режима.

## 2026-08-19 — D014: Main должен оставаться рабочим

После появления Android-кода существенные изменения выполняются через отдельные ветки и желательно PR. CI добавляется после появления Gradle-проекта и должен как минимум запускать unit tests и debug build.

Не merge код с красной сборкой/тестами.

## 2026-08-19 — D015: Полный порядок 33 букв пока не фиксируется окончательно

Для M1 достаточно `А` и `М`. Полный curriculum фиксируется отдельной версией до M5 после проверки TTS, distractors, визуально похожих групп и домашних наблюдений.

Фактическая confusion matrix конкретного ребёнка имеет приоритет при персональной тренировке над заранее предполагаемыми парами.

## 2026-08-19 — D016: Разделение ролей между AI

Рабочая модель проекта:

- Gemini Web — Product Lead / Orchestrator: обсуждение продукта, анализ, декомпозиция, маршрутизация и подготовка проверенных task packet;
- ChatGPT — основной Repository Engineer и Code Reviewer: изменения в GitHub, код, документация, Issues/PR и статический контроль;
- Gemini Android Studio Agent — только Local Android Specialist для IDE/SDK/Gradle/runtime/device/Logcat/Android-specific проблем;
- владелец — Product Owner и исполнитель простых действий Git/Run без расхода Agent Mode.

Commit/push/pull, обычный Run, pure Kotlin и JVM unit tests не являются задачами для Android Studio Agent по умолчанию.

## 2026-08-19 — D017: AI Decision Firewall и обязательный preflight

Task packet любого AI не создаёт новое продуктовое решение.

Перед выдачей и перед исполнением task packet обязательно различать:

- нормативные решения (`DECISIONS`, Product Spec, LearningEngine, Curriculum, DoD);
- фактический код;
- статус проекта;
- доказательства tests/build/emulator/device/owner acceptance.

Если код расходится с нормативной документацией, это implementation drift, а не автоматическое изменение спецификации.

AI не вправе без явного решения владельца:

- менять состав букв уровня или количество вопросов;
- придумывать критерии прохождения;
- менять mastery states/thresholds, веса, retry, level unlock или curriculum;
- записывать своё предложение как принятое решение;
- легализовать самовольное изменение кода простой синхронизацией документации;
- закрывать milestone без выполнения всех обязательных критериев Definition of Done.

Если DoD требует проверку на физическом устройстве, эмулятор не считается её заменой.

Gemini Web обязан самостоятельно проводить preflight task packet, а ChatGPT обязан повторно сверять task packet с актуальным репозиторием и не исполнять небезопасные продуктовые пункты task packet. Владелец не должен каждый раз вручную использовать одну нейросеть для проверки другой.

## 2026-08-19 — D018: Согласованные параметры Milestone 1 — А/М и 10 вопросов

`DECISION_SOURCE: OWNER`

Для M1 утверждены:

- Level 1: буквы `А` и `М`;
- одна тренировочная сессия: ровно 10 вопросов;
- результат имеет дискретность 10 процентных пунктов;
- 8 правильных ответов из 10 соответствуют 80%.

Эта запись устраняет implementation drift, при котором фактическая реализация содержала `А/О` и 8 вопросов. Она не является новым изменением полного Curriculum: нормативный M1-набор `А/М` уже был зафиксирован в D015 и `docs/CURRICULUM.md`.

В рамках этой корректировки не меняются LearningPolicy v1, веса букв, retry interval, mastery states и пороги разблокировки. `learningPolicyVersion` и `curriculumVersion` не повышаются, поскольку код возвращается к уже утверждённому нормативному поведению.

## 2026-08-19 — D019: M1 принят владельцем; незавершённые требования явно перенесены в M2

`DECISION_SOURCE: OWNER`

Владелец успешно проверил M1 на реальном Android-устройстве и принял реализованный вертикальный срез: Level 1 `А/М`, 10 вопросов, звук/TTS, выбор ответа, сохранение истории и основной пользовательский поток.

M1 считается `DONE` по скорректированному owner-approved gate. При этом следующие ранее записанные требования **не считаются реализованными** и не удаляются из roadmap, а обязательным образом переносятся в M2:

- разбивка результата отдельно по `А` и `М`;
- retry-механика: ошибочная target-буква должна возвращаться позднее по управляемому правилу;
- декларация `<queries>` для `android.intent.action.TTS_SERVICE` в Android Manifest, если системный TTS остаётся доступным fallback.

Этот перенос является изменением milestone scope/gate владельцем, а не утверждением, что перечисленные функции уже существуют. Они должны быть реализованы и проверены в следующей итерации вместе с M2.

## 2026-08-19 — D020: Гибридная аудио-архитектура M2 — локальное аудио first, TTS fallback

`DECISION_SOURCE: OWNER`

Начиная с M2 основной источник озвучки названий букв — заранее подготовленные локальные аудиофайлы (`WAV`/`OGG` в `res/raw`). Системный Android TTS сохраняется как fallback на случай отсутствия/ошибки локального ассета.

Архитектура должна быть скрыта за единым интерфейсом `AudioPlayer`, чтобы UI и LearningEngine не зависели от конкретного механизма воспроизведения. Для коротких локальных ассетов допускается `SoundPool`, для более длинных/редких — `MediaPlayer` либо эквивалентное простое Android API; точный выбор реализации определяется в M2 без изменения продуктового решения `pre-recorded first + TTS fallback`.

Аудиофайлы в рамках закрытия M1 не генерируются и не добавляются. Реализация AudioPlayer, локальных ассетов, fallback и требуемой TTS service visibility относится к M2.

## 2026-08-19 — D021: Curriculum Levels 1–3 и 80% level unlock

`DECISION_SOURCE: OWNER`

Владелец утвердил для M2 следующую частичную версию Curriculum:

- Level 1 вводит `А`, `М`; рабочий пул: `А`, `М`;
- Level 2 вводит `О`, `У`; рабочий пул: `А`, `М`, `О`, `У`;
- Level 3 вводит `С`, `Н`; рабочий пул: `А`, `М`, `О`, `У`, `С`, `Н`;
- каждая сессия содержит ровно 10 вопросов;
- старые буквы сохраняются в пуле последующих уровней;
- distractors берутся из уже доступного пула и не совпадают с target.

Правило level unlock:

- следующий уровень разблокируется после завершённой сессии текущего уровня с accuracy >= 80%;
- при 10 вопросах это минимум `8/10` правильных ответов;
- неполная сессия не разблокирует следующий уровень.

D021 является новым явным решением владельца и заменяет прежний ориентировочный критерий `recent accuracy >=85%` плюс дополнительные delayed-условия **именно для открытия следующего игрового уровня**, ранее описанный в `LEARNING_ENGINE.md` для LearningPolicy v1. Delayed success и mastery-state остаются важными для оценки знания и адаптивного повторения, но в этой версии не являются дополнительным gate для level unlock.

Поскольку меняются Curriculum и level-unlock behavior:

- `curriculumVersion = 2`;
- `learningPolicyVersion = 2`.

Накопленные Attempt старых версий не переписываются задним числом.

## 2026-08-20 — D022: LearningPolicy v3 — adaptive mastery, weighted selection и retry spacing

`DECISION_SOURCE: OWNER`

Текущая инструкция владельца для M2.4 явно меняет ранее записанную четырёхступенчатую mastery-модель. Поэтому она является новым owner decision, несмотря на маркировку task packet как `EXISTING_DECISION`.

Для LearningPolicy v3 утверждено:

- mastery states: `INTRODUCED`, `PRACTICING`, `MASTERED`;
- `INTRODUCED`: менее 3 показов/валидных попыток;
- `PRACTICING`: от 3 попыток и до выполнения критерия `MASTERED`, в том числе при recent accuracy <85%;
- `MASTERED`: минимум 5 попыток и recent accuracy >=85%;
- recent accuracy использует окно до последних 10 попыток, согласованное с `SUCCESS_METRICS.md`;
- базовый вес `MASTERED = 1.0`;
- `PRACTICING` имеет вес от `2.0` до `3.0` в зависимости от доли недавних ошибок;
- `INTRODUCED` имеет повышенный вес `2.0`;
- после ошибки target ставится в retry queue и при достаточном остатке сессии возвращается после 2–4 других вопросов;
- внутрисессионный delayed success валиден при spacing >=2 других вопросов;
- сильная буква сохраняет ненулевой шанс выбора;
- 10 вопросов и level unlock >=80% / 8 из 10 по D021 не меняются;
- Curriculum v2 и Room schema 2 не меняются.

Поскольку изменены mastery states, thresholds, weights и retry behavior, `learningPolicyVersion` повышается с `2` до `3`. Исторические Attempt старых версий не переписываются; совместимые поля accuracy/error history могут использоваться как вход для новой политики.
