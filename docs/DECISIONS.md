# Decision log

## 2026-08-19 — D001: Android-only MVP

Первая версия — нативное Android-приложение на Kotlin/Jetpack Compose.

## 2026-08-19 — D002: Названия букв, без звуков

MVP тренирует визуальную букву и её название. Фонетика/звуки букв пока не внедряются.

## 2026-08-19 — D003: Уровни + адаптивное повторение

Прогресс оформляется уровнями и наградами, но учебный движок продолжает повторять старые буквы и чаще возвращает слабые.

## 2026-08-19 — D004: Статистика и слабые буквы

Обязательны статистика по каждой букве, список проблемных букв и confusion matrix. Слабые буквы можно тренировать отдельно.

## 2026-08-19 — D005: Никакой суточной блокировки

3–7 минут — рекомендуемая сессия, а не лимит. После неё и после повторного входа занятия доступны.

## 2026-08-19 — D006: Рисование исключено

Рисование/проверка написания буквы не входят в MVP, чтобы ускорить разработку и тестирование.

## 2026-08-19 — D007: Слоги/слова позже

`МА → МО → МУ`, слова и чтение — отдельное развитие после базового тренажёра букв.

## 2026-08-19 — D008: Speech recognition отдельным экспериментом

Автоматическое распознавание произнесённого названия буквы планируется, но не блокирует MVP. Неуверенное распознавание не считается ошибкой ребёнка.

## 2026-08-19 — D009: Сначала семейный пилот, затем решение о публичном продукте

Первая цель — работающий локальный инструмент для реального домашнего использования. Backend, аккаунты, массовая продуктовая инфраструктура и требования публичного продукта не должны усложнять ранний пилот.

Решение о публикации принимается после накопления реальной статистики и проверки UX/полезности.

## 2026-08-19 — D010: Успех измеряется метриками знания, а не активностью

Основные метрики: accuracy по букве, response time, delayed success/retention, confusion rate и количество устойчиво освоенных букв.

Звёзды, минуты, открытые уровни и серия занятий — только мотивационные/активностные показатели.

## 2026-08-19 — D011: LearningPolicy и Curriculum версионируются

Изменения порогов mastery, весов, retry, level unlock и curriculum не должны происходить неявно.

После M1 должны использоваться отдельные версии:

- `learningPolicyVersion`;
- `curriculumVersion`;
- `databaseSchemaVersion`.

Изменение поведения требует обновления документации и тестов.

## 2026-08-19 — D012: Parent mode нужен в MVP

Детский основной поток остаётся простым. Статистика, ручной выбор букв, настройки и сброс прогресса относятся к родительскому режиму/настройкам и не должны загромождать детский экран.

Сложная авторизация родителя в семейном MVP не требуется.

## 2026-08-19 — D013: Локальные данные и privacy by default

До отдельного решения:

- нет backend;
- нет аккаунтов;
- нет analytics SDK;
- нет рекламных SDK;
- нет передачи учебной статистики разработчику;
- аудио ребёнка не сохраняется.

Микрофон запрашивается только при явном использовании экспериментального ASR-режима.

## 2026-08-19 — D014: Main должен оставаться рабочим

После появления Android-кода существенные изменения выполняются через отдельные ветки и желательно PR. CI добавляется после появления Gradle-проекта и должен как минимум запускать unit tests и debug build.

Не merge код с красной сборкой/тестами.

## 2026-08-19 — D015: Полный порядок 33 букв пока не фиксируется окончательно

Для M1 достаточно `А` и `М`. Полный curriculum фиксируется отдельной версией до M5 после проверки TTS, distractors, визуально похожих групп и домашних наблюдений.

Фактическая confusion matrix конкретного ребёнка имеет приоритет при персональной тренировке над заранее предполагаемыми парами.

## 2026-08-19 — D016: Разделение ролей между AI

Рабочая модель проекта:

- Gemini Web — Product Lead / Orchestrator: обсуждение продукта, анализ, декомпозиция, маршрутизация и подготовка проверенных task packet;
- ChatGPT — основной Repository Engineer и Code Reviewer: изменения в GitHub, код, документация, Issues/PR и статический контроль;
- Gemini Android Studio Agent — только Local Android Specialist для IDE/SDK/Gradle/runtime/device/Logcat/Android-specific проблем;
- владелец — Product Owner и исполнитель простых действий Git/Run без расхода Agent Mode.

Commit/push/pull, обычный Run, pure Kotlin и JVM unit tests не являются задачами для Android Studio Agent по умолчанию.

## 2026-08-19 — D017: AI Decision Firewall и обязательный preflight

Task packet любого AI не создаёт новое продуктовое решение.

Перед выдачей и перед исполнением task packet обязательно различать:

- нормативные решения (`DECISIONS`, Product Spec, LearningEngine, Curriculum, DoD);
- фактический код;
- статус проекта;
- доказательства tests/build/emulator/device/owner acceptance.

Если код расходится с нормативной документацией, это implementation drift, а не автоматическое изменение спецификации.

AI не вправе без явного решения владельца:

- менять состав букв уровня или количество вопросов;
- придумывать критерии прохождения;
- менять mastery states/thresholds, веса, retry, level unlock или curriculum;
- записывать своё предложение как принятое решение;
- легализовать самовольное изменение кода простой синхронизацией документации;
- закрывать milestone без выполнения всех обязательных критериев Definition of Done.

Если DoD требует проверку на физическом устройстве, эмулятор не считается её заменой.

Gemini Web обязан самостоятельно проводить preflight task packet, а ChatGPT обязан повторно сверять task packet с актуальным репозиторием и не исполнять небезопасные продуктовые пункты. Владелец не должен каждый раз вручную использовать одну нейросеть для проверки другой.
