# Curriculum — управление набором букв и учебной последовательностью

Дата: 2026-08-21

## 1. Назначение

Этот документ задаёт правила, по которым буквы попадают в уровни и упражнения. Он отделяет учебное содержание от кода.

Runtime Curriculum после M2 остаётся `curriculumVersion = 2` с Levels 1–3. Решением владельца D024 утверждена целевая 8-уровневая структура, покрывающая все 33 русские буквы; её реализация относится к M3.2 и должна получить новую версию Curriculum.

## 2. Канонический алфавит

Для UI, статистики и будущего полного Curriculum используется порядок:

`А Б В Г Д Е Ё Ж З И Й К Л М Н О П Р С Т У Ф Х Ц Ч Ш Щ Ъ Ы Ь Э Ю Я`.

Всего: 33 буквы.

Для каждой буквы curriculum хранит/задаёт:

- `symbol`;
- `spokenName`;
- `stageIntroduced`;
- `confusableWith`;
- `preferredDistractors`;
- `avoidEarlyPairingWith`;
- `enabled`.

UI не должен самостоятельно задавать состав уровней.

## 3. Runtime Curriculum v2 — Levels 1–3

`curriculumVersion = 2`

### Level 1

Новые буквы: `А`, `М`.

Рабочий пул: `А`, `М`.

### Level 2

Новые буквы: `О`, `У`.

Рабочий пул: `А`, `М`, `О`, `У`.

### Level 3

Новые буквы: `С`, `Н`.

Рабочий пул: `А`, `М`, `О`, `У`, `С`, `Н`.

Каждая сессия содержит 10 вопросов. Открытие нового уровня не удаляет старые буквы из рабочего пула.

## 4. D024 — целевой Curriculum на 8 уровней

Владелец утвердил:

- всего 8 игровых уровней;
- все 33 русские буквы должны быть введены к Level 8;
- Levels 1–3 сохраняют состав D021;
- Levels 4–8 вводят оставшиеся 27 букв;
- накопленный пул всегда включает ранее введённые буквы;
- правило 10 вопросов и unlock `>=80%` / `8 из 10` не меняется только из-за расширения состава букв.

Оставшиеся 27 букв:

`Б В Г Д Е Ё Ж З И Й К Л П Р Т Ф Х Ц Ч Ш Щ Ъ Ы Ь Э Ю Я`.

В текущем task packet отсутствует сама owner-approved матрица распределения этих 27 букв между Levels 4–8. Поэтому M3.1 **не фиксирует выдуманный порядок**. Перед M3.2 матрица D024 должна быть внесена в этот раздел буквально; только затем код `ApprovedCurriculum` может быть расширен и `curriculumVersion` повышен.

## 5. Правила добавления новой буквы

Новая буква включается в runtime только если:

- её положение утверждено в versioned Curriculum;
- озвучка проверена или существует корректный TTS fallback;
- LearningEngine продолжает показывать старые буквы;
- distractors формируются только из доступного пула и не совпадают с target;
- изменение покрыто тестами.

## 6. Похожие и путаемые буквы

Потенциально похожие пары используются осторожно как curriculum input. Фактическая confusion matrix конкретного ребёнка имеет приоритет для персонального повторения.

Примеры для проверки: `Н/П`, `Ш/Щ`, `Ь/Ъ`, `И/Й`, `В/Б`.

## 7. Distractors

- distractor не равен target;
- distractor берётся из уже доступного рабочего пула;
- старые изученные буквы остаются допустимыми distractors;
- позиции ответов перемешиваются независимо от target;
- фактически путаемая пара может получать приоритет через LearningPolicy.

## 8. Озвучка букв

Для каждой буквы `spokenName` задаётся явно. По D020 основной источник — локальный asset в `res/raw`, системный Android TTS — fallback. Новые локальные файлы для оставшихся 27 букв относятся к M3.2.

## 9. Версионирование

Текущий runtime:

`curriculumVersion = 2`.

D024 требует новой версии при фактическом включении Levels 4–8. До реализации M3.2 Attempt продолжают сохранять runtime version 2; задним числом исторические записи не переписываются.

## 10. Что Curriculum не решает

Curriculum определяет содержание и последовательность, но не решает:

- какую букву выбрать следующей внутри сессии — это LearningEngine;
- когда буква `MASTERED` — это LearningPolicy;
- long-term retention decay — это LearningPolicy/Spaced Repetition;
- игровую награду — UX/Game layer.
