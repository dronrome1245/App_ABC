# Risk Register — App_ABC

Дата: 2026-08-19

Шкала:

- Probability: Low / Medium / High
- Impact: Low / Medium / High
- Status: Open / Controlled / Accepted / Closed

## R1 — ребёнок запоминает расположение кнопок, а не букву

- Probability: High
- Impact: High
- Status: Open
- Признак: точность высокая при фиксированных позициях и падает после перестановки.
- Меры:
  - случайно менять положение вариантов;
  - хранить позицию ответа при необходимости для диагностики;
  - не использовать один и тот же шаблон раскладки;
  - проверить в тест-плане.

## R2 — случайное угадывание создаёт ложное ощущение знания

- Probability: High на уровнях с 2 вариантами
- Impact: High
- Status: Controlled
- Меры:
  - не повышать mastery по 1–2 правильным ответам;
  - использовать delayed checks;
  - учитывать серию попыток;
  - постепенно увеличивать число вариантов;
  - использовать межсессионное удержание.

## R3 — TTS неверно или неестественно произносит название буквы

- Probability: Medium
- Impact: High
- Status: Open
- Меры:
  - хранить `spokenName` отдельно от символа;
  - проверять каждую букву на реальном устройстве до включения;
  - при необходимости использовать альтернативную строку или локальную запись взрослого.

## R4 — алгоритм слишком быстро открывает новые буквы

- Probability: Medium
- Impact: High
- Status: Open
- Меры:
  - версия LearningPolicy;
  - критерии из `SUCCESS_METRICS.md`;
  - не считать серию подряд устойчивым знанием;
  - delayed checks;
  - анализировать откат accuracy после открытия следующего уровня.

## R5 — старые буквы перестают повторяться

- Probability: Medium
- Impact: High
- Status: Controlled
- Меры:
  - ненулевой вес старых букв;
  - unit test на сохранение старых букв в пуле;
  - отдельный инвариант LearningEngine.

## R6 — проблемная буква повторяется слишком часто и вызывает угадывание/усталость

- Probability: Medium
- Impact: Medium
- Status: Open
- Меры:
  - retry через 2–4 других задания;
  - лимит одинаковых target подряд;
  - контроль доли weak items;
  - сессионный лимит без суточной блокировки.

## R7 — игровая оболочка вытесняет учебную цель

- Probability: Medium
- Impact: Medium
- Status: Controlled
- Меры:
  - звёзды/награды не управляют выбором вопросов;
  - отсутствие магазина/монет/жизней в MVP;
  - продуктовые метрики знания отдельно от игровых.

## R8 — ребёнок расстраивается из-за ошибок

- Probability: Medium
- Impact: High
- Status: Controlled
- Меры:
  - спокойная коррекция;
  - без «НЕПРАВИЛЬНО!» на весь экран;
  - без потери жизней и обнуления;
  - короткая позитивная обратная связь.

## R9 — статистика интерпретируется как медицинский диагноз

- Probability: Low
- Impact: High
- Status: Controlled
- Меры:
  - называть состояния игровыми метриками;
  - явно писать, что приложение не диагностирует нарушения;
  - не использовать медицинские ярлыки.

## R10 — AI самовольно меняет учебный алгоритм, scope или статус milestone

- Probability: High при длительном vibe coding
- Impact: High
- Status: Controlled
- Меры:
  - `docs/AI_ROLES.md` содержит обязательные Routing Gate, Decision Firewall, Implementation Drift Rule и Preflight Gate;
  - `AGENTS.md` требует независимой сверки task packet с репозиторием перед изменением;
  - task packet не является новым источником продуктовой истины;
  - изменение порогов/весов/curriculum/DoD требует `DECISION_SOURCE` и решения владельца;
  - код не может автоматически переписывать нормативную документацию;
  - Gemini Web обязан проверять task packet до выдачи;
  - ChatGPT обязан не выполнять небезопасные продуктовые пункты task packet;
  - emulator/build/tests/physical-device/owner acceptance фиксируются отдельно;
  - изменения поведения требуют версии и unit tests.
- Триггер повторного открытия High-risk: AI снова фиксирует несуществующее решение владельца, закрывает milestone без DoD или Android Studio Agent выходит за локальный runtime-scope.

## R11 — main становится нерабочим после AI-изменения

- Probability: Medium
- Impact: High
- Status: Open до появления стабильного CI
- Меры:
  - `main` считается всегда рабочей веткой;
  - существенные кодовые задачи выполнять через feature branch + PR;
  - CI: unit tests + debug build;
  - не merge при красной сборке.

## R12 — потеря/повреждение статистики после изменения Room schema

- Probability: Medium
- Impact: High
- Status: Open
- Меры:
  - не использовать destructive migration для реальных данных без явного решения;
  - тестировать migrations после появления стабильной базы;
  - схема базы версионируется;
  - перед рискованными изменениями предусмотреть export/backup strategy при необходимости.

## R13 — в публичный GitHub попадают персональные данные/аудио/секреты

- Probability: Medium
- Impact: High
- Status: Open
- Меры:
  - не сохранять аудио в репозитории;
  - не коммитить реальные персональные тестовые данные;
  - `.gitignore` для ключей и локальных файлов;
  - секреты только вне Git;
  - перед release выполнить privacy audit.

## R14 — speech recognition ошибочно оценивает детскую речь

- Probability: High
- Impact: High
- Status: Controlled проектным решением
- Меры:
  - отдельный экспериментальный режим;
  - `NOT_RECOGNIZED` не является ошибкой;
  - не использовать ASR для mastery до проверки качества;
  - тестировать на реальной детской речи.

## R15 — слишком длинная сессия снижает качество ответов

- Probability: Medium
- Impact: Medium
- Status: Controlled
- Меры:
  - ориентир 3–7 минут;
  - позитивный экран завершения;
  - продолжение только по желанию;
  - анализировать ухудшение accuracy/response time к концу сессии.

## R16 — curriculum оказывается неудачным

- Probability: Medium
- Impact: High
- Status: Open
- Меры:
  - curriculum version;
  - не фиксировать полный порядок без тестирования;
  - фактическая confusion matrix имеет приоритет над предположениями;
  - корректировать последовательность по данным и при необходимости консультироваться со специалистом.

## R17 — Android Studio Agent расходует лимит и меняет проект вне локальной задачи

- Probability: Medium
- Impact: Medium
- Status: Controlled
- Меры:
  - Agent admission только при `ROUTING: ANDROID_STUDIO_AGENT` + `WHY_AGENT_REQUIRED`;
  - commit/push/pull/обычный Run/pure Kotlin не маршрутизируются в Agent;
  - Git-only request запрещает rebase/reset/force push и любые изменения проекта;
  - `prompts/ANDROID_STUDIO_AGENT_PROMPT.md` содержит scope lock;
  - после задачи Agent обязан остановиться и вернуть точный список изменений.

## Правило работы с рисками

Перед завершением каждого milestone AI должен проверить:

- новые риски;
- сработавшие триггеры;
- High-риски без меры контроля.

Если риск меняет продуктовую/архитектурную стратегию, решение фиксировать в `DECISIONS.md` только после реального принятия владельцем.
