# Privacy & Release — App_ABC

Дата: 2026-08-19

## 1. Базовая политика MVP

До отдельного решения продукт работает локально на устройстве.

По умолчанию:

- нет аккаунта;
- нет backend;
- нет облачной синхронизации;
- нет рекламных SDK;
- нет аналитических SDK;
- нет передачи учебной статистики разработчику;
- нет сохранения аудиозаписей ребёнка.

## 2. Какие данные допустимо хранить локально

Для работы приложения:

- история попыток;
- выбранные ответы;
- время ответа;
- даты/время сессий;
- прогресс по буквам;
- confusion matrix;
- настройки приложения;
- версия curriculum/LearningPolicy.

Не хранить ФИО, адрес, школу, дату рождения и другие персональные данные, если они не нужны функции продукта.

## 3. Профиль ребёнка

В семейном MVP отдельный профиль не обязателен.

Если позднее появятся несколько профилей на одном устройстве, использовать нейтральное локальное имя/аватар и не требовать реальных персональных данных.

## 4. Микрофон

Разрешение `RECORD_AUDIO` запрашивать только при явном входе в экспериментальный режим распознавания речи.

До M6 приложение не должно запрашивать микрофон без необходимости.

При ASR:

- объяснить взрослому, зачем нужен микрофон;
- учитывать, что конкретный speech recognizer может использовать сетевую обработку;
- on-device recognition предпочитать, если доступно и надёжно;
- `NOT_RECOGNIZED` не считать ошибкой ребёнка.

## 5. Аудиозаписи

По умолчанию не сохранять и не экспортировать аудио.

Если когда-либо потребуется временная запись для отладки:

- это отдельное решение владельца;
- только на устройстве/в явно выбранном месте;
- не коммитить в публичный GitHub;
- предусмотреть удаление;
- не включать такую запись в release по умолчанию.

## 6. Удаление данных

До release candidate приложение должно иметь понятную возможность:

- сбросить учебный прогресс;
- удалить локальную историю попыток;
- подтвердить опасное действие перед удалением.

Для семейного пилота допустима функция в Parent mode/Settings.

## 7. Публичный репозиторий

Репозиторий сейчас публичный.

Запрещено коммитить:

- реальные персональные данные ребёнка;
- аудиозаписи;
- локальные базы с реальной статистикой;
- signing keys;
- keystore password;
- API keys/secrets;
- приватные диагностические выгрузки.

При появлении новых типов локальных файлов обновлять `.gitignore`.

## 8. Crash reporting / analytics

Не подключать автоматически.

Если позднее понадобится crash reporting или аналитика:

1. определить конкретную пользу;
2. оценить какие данные отправляются;
3. проверить требования для детской аудитории;
4. обновить privacy documentation;
5. получить отдельное решение владельца.

## 9. Google Play release gate

Перед публикацией нельзя полагаться на старые требования магазина.

Нужно непосредственно перед release проверить актуальные требования Google Play, особенно относящиеся к:

- детской/семейной аудитории;
- сбору данных;
- микрофону;
- Data safety;
- рекламе, если она когда-либо появится;
- target SDK;
- тестированию/публикации аккаунта разработчика.

## 10. Release checklist

Перед M7 completion:

- [ ] release build собирается;
- [ ] debug-функции выключены/изолированы;
- [ ] секреты отсутствуют в Git;
- [ ] signing key хранится безопасно;
- [ ] local data reset доступен;
- [ ] privacy text соответствует фактическому поведению;
- [ ] микрофон используется только по назначению;
- [ ] аудио не сохраняется без согласованной функции;
- [ ] актуальные Google Play policies проверены;
- [ ] Data safety заполнен по фактическим данным;
- [ ] закрытое тестирование завершено;
- [ ] критические crash/data-loss bugs закрыты;
- [ ] принято явное решение о публикации.

## 11. Лицензия исходного кода

Публичность GitHub не означает автоматически выбранную open-source лицензию.

До распространения/приёма внешних вкладов владелец должен отдельно решить:

- оставить код source-available без лицензии;
- сделать репозиторий private;
- выбрать open-source лицензию.

AI не должен добавлять лицензию без решения владельца.
