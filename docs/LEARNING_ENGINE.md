# Learning Engine — алгоритм обучения

Дата: 2026-08-20

## 1. Главный принцип

Приложение тренирует извлечение из памяти. После ошибки буква возвращается через несколько других вопросов; старые буквы продолжают появляться после открытия новых уровней. Игровой уровень и учебное состояние буквы — разные сущности.

## 2. Версия политики

Текущая нормативная версия после D022:

`learningPolicyVersion = 3`

LearningPolicy v3 сохраняет D021 без изменений: сессия содержит 10 вопросов, следующий игровой уровень открывается при результате >=80% (минимум 8/10). Изменения v3 относятся к mastery, weighted selection, retry и delayed checks.

Исторические Attempt старых версий не переписываются.

## 3. Mastery states — LearningPolicy v3

- `INTRODUCED` — менее 3 валидных попыток;
- `PRACTICING` — от 3 попыток до выполнения критерия `MASTERED`;
- `MASTERED` — минимум 5 попыток и recent accuracy >=85%.

Recent accuracy считается по окну до последних 10 попыток по букве. При 5 попытках 4/5 = 80% и статус остаётся `PRACTICING`.

Это внутренняя учебная метрика, а не медицинская оценка.

## 4. Данные

### Attempt

Минимально:

- `id`;
- `timestamp`;
- `sessionId`;
- `levelId`;
- `targetLetter`;
- `selectedLetter`;
- `isCorrect`;
- `responseTimeMs`;
- `learningPolicyVersion`;
- `curriculumVersion`.

### Производные данные

Для адаптивного выбора могут вычисляться/кэшироваться:

- total attempts;
- correct attempts;
- recent accuracy;
- recent errors;
- delayed successes;
- last seen;
- mastery state;
- confusion `target -> selectedWrong`.

Сырые Attempt остаются источником подробной истории.

## 5. Взвешенный выбор target

Пул = буквы текущего уровня + ранее изученные.

Централизованные веса v3:

- `MASTERED = 1.0`;
- `INTRODUCED = 2.0`;
- `PRACTICING = 2.0...3.0` в зависимости от доли ошибок в recent window.

Чем больше недавних ошибок у `PRACTICING`, тем ближе вес к 3.0. `MASTERED` всегда сохраняет ненулевой шанс.

Одна target-буква не должна появляться более двух раз подряд. Позиция правильного ответа перемешивается независимо от target.

## 6. Retry queue после ошибки

После неправильного ответа:

1. target ставится в `InSessionRetryQueue`;
2. при достаточном остатке 10-вопросной сессии target не выбирается обычным weighted flow до момента retry;
3. retry возвращается после 2–4 других вопросов;
4. немедленного повтора быть не должно;
5. повторная ошибка может породить новый retry только если в сессии остаётся место для требуемого spacing;
6. фиксированная длина сессии 10 вопросов не увеличивается ради retry.

Если ошибка произошла слишком поздно и физически невозможно разместить 2 других вопроса и retry до конца 10-вопросной сессии, новый retry не планируется.

## 7. Delayed success

Внутрисессионный delayed success валиден, если:

- target уже предъявлялась ранее;
- между двумя предъявлениями было минимум 2 других вопроса;
- повторный ответ правильный.

Межсессионные интервалы могут анализироваться по сохранённым Attempt, когда данные реально существуют. Delayed success не является дополнительным gate для открытия уровня по D021.

## 8. Confusion

При каждой ошибке увеличивается счётчик пары:

`targetLetter -> selectedWrongLetter`.

Фактическая confusion history остаётся доступна из Attempt и может использоваться последующими режимами слабых букв/Parent mode.

## 9. Открытие уровня — без изменений

Следующий уровень разблокируется, если:

- завершена полная сессия;
- ровно 10 вопросов;
- accuracy >=80%;
- минимум 8 правильных ответов.

7/10 не открывает; 8/10, 9/10 и 10/10 открывают. Mastery state не заменяет этот gate.

## 10. Случайность и тестируемость

AdaptiveSessionGenerator — pure Kotlin и принимает `java.util.Random`/фиксированный seed. UI не выбирает target самостоятельно.

Детерминированные тесты должны подтверждать:

- distractor не равен target;
- ошибка возвращает target с spacing >=2, когда в сессии есть место;
- retry не превращается в бесконечный цикл;
- нет серии одной target длиннее двух;
- `PRACTICING` получает больший статистический вес, чем `MASTERED`;
- `MASTERED` имеет ненулевой шанс;
- старые буквы не исчезают после открытия новых;
- delayed success требует допустимого интервала;
- confusion обновляется по правильной паре;
- версия LearningPolicy меняется только через Decision Log.

## 11. Что LearningEngine не решает

- визуальный дизайн;
- игровые награды;
- полный порядок 33 букв;
- медицинские выводы;
- распознавание речи.
