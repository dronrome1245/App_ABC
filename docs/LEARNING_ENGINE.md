# Learning Engine — алгоритм обучения

Дата: 2026-08-19

## 1. Главный принцип

Приложение должно тренировать извлечение из памяти, а не только многократный показ одной буквы. После ошибки букву нужно вернуть через несколько других вопросов. Старые буквы должны периодически появляться после открытия новых уровней.

Игровой уровень и учебное состояние буквы — разные сущности.

## 2. Версия политики

Текущая нормативная версия после решения D021:

`learningPolicyVersion = 2`

LearningPolicy v2 наследует правила v1, кроме критерия открытия следующего игрового уровня: вместо раннего ориентировочного `>=85%` + дополнительных delayed-условий используется owner-approved gate `>=80%` на завершённой сессии из 10 вопросов (минимум 8/10).

Изменения поведения, влияющие на выбор вопросов/mastery/открытие уровней, нельзя менять без:

- записи в `DECISIONS.md`;
- повышения `learningPolicyVersion`;
- обновления unit tests;
- при необходимости повторной оценки накопленной статистики.

## 3. Состояния буквы

- `NEW`
- `LEARNING`
- `FAMILIAR`
- `STABLE`

Это внутренняя игровая/учебная метрика, а не медицинская оценка.

## 4. Данные

### Attempt

Минимально:

- `id`;
- `timestamp`;
- `sessionId`;
- `levelId`;
- `exerciseType`;
- `targetLetter`;
- `selectedLetter`;
- `isCorrect`;
- `responseTimeMs`;
- `learningPolicyVersion`;
- `curriculumVersion`.

### LetterProgress

Можно вычислять или кэшировать:

- `totalAttempts`;
- `correctAttempts`;
- `recentAccuracy`;
- `recentMedianResponseTime`;
- `consecutiveCorrect`;
- `lastSeenAt`;
- `lastErrorAt`;
- `masteryState`.

### Confusion

Для каждой ошибки увеличивать счётчик:

`targetLetter -> selectedWrongLetter`.

## 5. Проблемная буква — LearningPolicy v2

Считать букву проблемной, если выполнено хотя бы одно:

- минимум 5 попыток и recent accuracy < 80%;
- минимум 2 ошибки в последних 5 попытках;
- одна и та же confusion pair повторилась >= 2 раз;
- response time заметно хуже личной медианы по знакомым буквам.

Последний критерий не должен быть единственным основанием на раннем этапе.

Пороги хранятся централизованно, а не magic numbers в UI.

## 6. Выбор следующего вопроса

1. Пул = буквы текущего уровня + ранее изученные.
2. Повысить вес:
   - новой буквы;
   - букв с недавними ошибками;
   - слабых букв;
   - давно не появлявшихся букв.
3. Сильные буквы сохраняют ненулевой вес.
4. Не давать одну цель слишком много раз подряд.
5. Учитывать retry queue.
6. Позиции вариантов ответа перемешивать независимо от target.

Ориентир при достаточном пуле:

- около 50% новые/слабые;
- около 30% обычное повторение;
- около 20% сильные старые.

Это конфигурация LearningPolicy, а не вечная константа.

## 7. После ошибки

1. Показать корректный ответ.
2. При необходимости повторить spokenName/аудио.
3. Поставить target в `retryQueue`.
4. Дать примерно 2–4 других задания, если пул позволяет.
5. Снова спросить target.
6. Позднее вернуть его в обычный поток.

Не повторять ошибочную букву много раз подряд.

## 8. Delayed success

Для повышения mastery важен правильный ответ после промежутка, а не только немедленный повтор.

Внутрисессионная delayed-проверка считается валидной, если между двумя предъявлениями target было минимум 2 других задания.

Межсессионные интервалы 6h+/24h+/7d+ используются как дополнительные метрики, когда такие данные появились естественным образом.

Delayed success влияет на mastery/качество знания, но по D021 **не является дополнительным условием level unlock** в LearningPolicy v2.

## 9. Открытие уровня — LearningPolicy v2

Не требуется ждать следующего календарного дня.

Следующий уровень разблокируется, если:

- завершена полная сессия текущего уровня;
- сессия содержит ровно 10 вопросов;
- accuracy >= 80%;
- при 10 вопросах это минимум 8 правильных ответов.

Результат 7/10 не открывает следующий уровень. Результат 8/10, 9/10 или 10/10 открывает.

Неполная сессия не открывает уровень даже при текущей точности >=80%.

Открытие следующего уровня не означает переход букв в `STABLE` и не отменяет повтор старых букв.

## 10. STABLE

Ориентироваться на `SUCCESS_METRICS.md`.

Для текущей policy:

- минимум 10 попыток;
- recent accuracy >= 90%;
- минимум 2 delayed successes;
- нет 2 ошибок подряд в последних 5 попытках;
- при наличии межсессионных данных — хотя бы один правильный ответ после перерыва 6h+.

Если межсессионных данных ещё нет, буква может оставаться `FAMILIAR`.

## 11. Тренировка слабых

В специальной тренировке:

- ориентировочно 70–80% вопросов — выбранные слабые буквы;
- остальные — знакомые контрольные буквы;
- позиции вариантов случайные;
- повторяющиеся фактические confusion pairs получают повышенный приоритет.

Нельзя делать режим, где всегда показаны только две известные проблемные буквы в фиксированных позициях.

## 12. Случайность и тестируемость

LearningEngine должен позволять передать источник случайности/seed в unit tests.

Тестовые сценарии должны быть воспроизводимы.

UI не должен самостоятельно выбирать следующую букву.

## 13. Инварианты LearningEngine

Обязательные:

- старая буква не исчезает полностью после открытия новой;
- ошибка возвращает target;
- retry не бесконечен;
- нет запрещённой длинной серии одной цели;
- слабая буква получает повышенный вес;
- сильная буква имеет ненулевой шанс;
- confusion matrix обновляется по правильной паре;
- история прошлых уровней не стирается;
- положение ответа не кодирует target;
- изменение версии политики не происходит неявно.

## 14. Что LearningEngine не решает

- визуальный дизайн;
- игровую награду;
- полный порядок 33 букв — `CURRICULUM.md`;
- медицинские выводы;
- распознавание речи.
