## Техническое задание (M1)

Создай Android-приложение в текущем репозитории.

Стек:

- Kotlin;
- Jetpack Compose;
- Material 3;
- Gradle Kotlin DSL;
- package: `com.dronrome1245.appabc`;
- minSdk 26 или выше, если текущие стабильные Android-инструменты обоснованно требуют другого решения;
- Room для попыток;
- ViewModel + StateFlow;
- Android TextToSpeech через маленький отдельный wrapper/service.

### Экран 1 — Главная

- название «Буквы»;
- кнопка «Начать»;
- небольшая подпись «Уровень 1 · А М»;
- пока без регистрации и профиля.

### Экран 2 — Упражнение

- две крупные кнопки `А` и `М`;
- позиции кнопок должны случайно меняться между вопросами;
- сверху нейтральный текст «Найди букву» без отображения ответа;
- кнопка повтора голосовой инструкции;
- TTS произносит целевое название буквы;
- использовать явно заданные `spokenName`, а не полагаться на произношение одиночного Unicode-символа;
- 10 вопросов в первом прототипе;
- нельзя выдавать одну и ту же цель более двух раз подряд;
- после ошибки правильный ответ спокойно подсветить/показать, без «жизней» и наказаний;
- ошибочную букву вернуть в очередь через несколько вопросов, а не обязательно немедленно;
- защита от двойного нажатия: один показ задания создаёт максимум одну Attempt.

### Данные попытки

Сохранять:

- targetLetter;
- selectedLetter;
- isCorrect;
- responseTimeMs;
- timestamp;
- sessionId;
- levelId;
- exerciseType.

Архитектуру данных подготовить так, чтобы после M1 без болезненной переделки добавить:

- learningPolicyVersion;
- curriculumVersion.

Если проще и безопаснее добавить эти поля сразу с начальными значениями `1`, сделать это сейчас.

### Session

При каждом запуске новой тренировочной серии создать `sessionId`, общий для 10 вопросов этой серии.

Повтор «Ещё раз» создаёт новую сессию.

### Экран 3 — Результат

После 10 вопросов показать:

- правильных ответов X/10;
- отдельную строку по А и М;
- кнопку «Ещё раз»;
- кнопку «На главную».

### LearningEngine

Учебный выбор следующего target вынести из Compose в чистый Kotlin-класс.

На M1 не реализовывать весь M2, но заложить минимальные инварианты:

- нет цели более двух раз подряд;
- после ошибки target возвращается позднее;
- выбор target не зависит от позиции UI;
- тестовый random/seed можно контролировать в unit tests.

### Тесты

Добавить unit-тесты как минимум на:

- запрет длинной серии одной цели;
- возврат ошибочной буквы в последующих вопросах;
- отсутствие бесконечного retry;
- воспроизводимость алгоритма при фиксированном test random/seed, если выбран такой подход.

Выполнить доступные Gradle unit tests и debug build.

### CI

После создания рабочего Gradle-проекта оцени возможность добавить минимальный GitHub Actions workflow: unit tests + debug build.

Если это заметно увеличивает объём M1 или требует отдельной отладки GitHub Actions, **не блокируй M1**: создай запись/Issue для M1.1 и укажи это в `PROJECT_STATUS.md`.

## Что НЕ делать

Не добавлять в этой задаче:

- весь алфавит;
- полноценную карту уровней;
- статистический dashboard;
- Parent mode;
- speech recognition;
- звуки букв/фонетику;
- слоги/слова;
- сложную игровую механику.
